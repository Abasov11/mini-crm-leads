# Mini-CRM для заявок агентства — проект до разработки

Тестовое задание, срок 3 дня.

## 1. Продукт
**Проблема.** Заявки агентства приходят в разные места: в бот, в личный Telegram менеджера, по звонку. Часть из них теряется, никто не видит, что с ними происходит, и их нельзя разложить по типам.
**Для кого.** Небольшое агентство из 1–5 человек, у которого основной канал — Telegram.
**Суть.** Все обращения попадают в один список сами, без ручного копирования. Менеджер ставит теги, видит лидов по тегу и ведёт статус.

## 2. Архитектура
Один Python-процесс на asyncio, одна база SQLite, один systemd-юнит:
```
Telegram-бот (aiogram 3, polling) ─┐
Подключённый аккаунт (Telethon) ───┼─► store.py (SQLite) ─► events (asyncio pub/sub) ─► SSE ─► браузер
Веб (FastAPI + Jinja2 + htmx) ─────┘
```
- Без брокера, Redis и микросервисов: на объёме агентства это лишнее, а деплой остаётся в одну команду.
- Новый лид появляется на открытой странице сам, через SSE (живой список), без перезагрузки.
- htmx нужен, чтобы фильтры и теги работали без перезагрузки страницы и без JS-сборки. Файл лежит локально, CDN не используется.

## 3. Данные
- `leads`: id, name, contact, request, source (`bot|telegram|manual`), status (`new|work|won|lost`), tg_user_id, tg_username, created_at, updated_at
- `messages`: id, lead_id, text, created_at — история переписки по лиду
- `tags`: id, name (уникально без учёта регистра), color; `lead_tags`: lead_id, tag_id
- `settings`: key/value — сессия подключённого Telegram и прочее

Источник хранится отдельным полем, а не тегом: его ставит система, и пользователь не должен его случайно снять. Теги — словарь агентства («сайт», «срочно», «B2B»).

## 4. Логика каналов
**Бот (п.1)** — анкета: /start → имя (кнопка «Да, я <имя из профиля>») → контакт (кнопка «Поделиться номером», кнопка «Пишите сюда, @username» или ввод текстом) → запрос → сводка с кнопками «Отправить» / «Заполнить заново» → лид. Каждая отправленная анкета — новый лид: у одного человека может быть несколько разных задач. /cancel прерывает анкету в любой момент. Если вместо кнопки прислали что-то не то, бот переспрашивает и не падает.
**Подключённый аккаунт (п.2)** — Telethon слушает входящие в личке. Пропускаем ботов, себя, служебный 777000 и людей из контактов: это коллеги и знакомые, а не лиды. Снять фильтр контактов можно в настройках. Склейка: если у этого человека уже есть открытый лид из Telegram (статус не won/lost), сообщение дописывается в его историю, иначе создаётся новый лид. Без склейки каждое «здравствуйте» и «вы тут?» превращалось бы в отдельный лид. Подключение — в настройках по QR-коду (Telethon qr_login), поддерживается пароль 2FA. Отключение = log_out.
**Вручную (п.3)** — форма: имя (обязательно), контакт, запрос, теги.
**Теги (п.4)** — в карточке: поле с автодополнением из уже существующих тегов, новый тег создаётся по Enter. В боковой панели — список тегов со счётчиками, клик фильтрует список. Фильтры складываются: тег + источник + статус + поиск.

## 5. Доступ
Вход по логину и паролю: в лидах контакты живых людей, поэтому открытой страницы со списком быть не должно. Две роли: `admin` (владелец) и `demo` (проверяющие, логин указан в документе). Demo может всё с лидами и тегами, но не может отключить или переподключить Telegram, иначе сломает демо. Cookie-сессия подписана, на всех POST проверяется Origin (CSRF), стоит лимит попыток входа.

## 6. Дизайн
Плоский стиль (ui-ux-pro-max: Flat Design, Inter). Фиолетовую палитру из подборки не берём: для рабочего инструмента лучше нейтральный slate и один акцент (indigo #4F46E5). Теги — 8 приглушённых цветов с контрастом ≥4.5:1. Тёмная тема по prefers-color-scheme.
- Десктоп: слева панель (Все / Источники / Статусы / Теги со счётчиками), справа таблица. Колонки: имя+контакт, запрос (одна строка), теги, источник, статус, время. Сверху поиск и кнопка «+ Лид».
- Мобильный (375px): панель превращается в горизонтальную ленту фильтров, таблица — в карточки.
- Карточка лида: поля правятся на месте, статус, теги, история сообщений, ссылка «Написать в Telegram» (t.me/username).
- Пустые состояния с подсказкой: «Лидов пока нет — напишите боту @…». Новый лид подсвечивается 2 секунды.
- Иконки — inline SVG (Lucide), эмодзи не используем. Видимый focus-ring, цели касания от 44px, учтён prefers-reduced-motion.

## 7. Деплой
Каталог проекта, venv, порт 127.0.0.1:8013, systemd `mini-crm.service`, nginx `crm.213-32-66-46.nip.io` (443 приходит через stream SNI → 8444), сертификат certbot webroot. Бота создаём через @BotFather от @SalatMalatt, отдельную Telethon-авторизацию для CRM — тоже от @SalatMalatt: основная сессия аккаунта уже занята другим сервисом, а одна сессия в двух процессах дает AUTH_KEY_DUPLICATED.

## 8. Сознательно за скобками
Ответ лиду из CRM, воронка и канбан, несколько менеджеров с назначением, импорт и экспорт, ИИ-разбор заявок и автотеги, WhatsApp и Instagram, уведомления менеджеру. Всё это — в «что бы сделал за неделю».

## 9. Definition of Done
1. Живая ссылка https открывается, вход demo работает.
2. Сообщение боту → анкета → лид появляется в открытом списке без перезагрузки.
3. Ручное добавление лида, с тегами.
4. Тег ставится и снимается, фильтр по тегу показывает нужных лидов, счётчики верные.
5. П.2: входящее в подключённый аккаунт → лид, повторное сообщение → в историю того же лида; контакты и боты игнорируются.
6. Мобильная вёрстка 375px без горизонтального скролла, тёмная тема.
7. Перезапуск сервиса не теряет данные, бот и userbot переподключаются.
8. Тесты store, анкеты и склейки зелёные; живой e2e бота пройден реальным сообщением.
9. Документ (набросок + разбор) по ссылке /doc и в PDF, текст прошёл через copywriter.
10. Приёмка вторым агентом «чего нет» по тексту задания.
